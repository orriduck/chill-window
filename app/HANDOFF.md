# 窗景 · 专注列车（交接文档）

一个以火车侧窗风景为核心体验的专注 App。当前运行时完整模拟检票上车、始发站停靠、发车、巡航、进站休息和抵达终点。

## 技术栈

- React 19 + TypeScript + Vite + Tailwind CSS + shadcn/ui
- Three.js WebGL：程序化地景、铁路工程、面对面软座车厢与天气
- Web Audio API：程序生成的车轮隆隆声、过轨声与进站提示音
- 纯前端，无后端或持久化

## 构建运行

```bash
npm install
npm run dev
npm run build
npm run lint
```

## 当前运行时

```
src/
├── pages/Home.tsx                    # 设置页、旅程状态机与乘客 HUD
├── engine/
│   ├── three/
│   │   ├── ThreeCanvas.tsx           # Three.js 生命周期与控制接口
│   │   ├── core/Camera.ts             # 唯一的列车运动、坡度与视角来源
│   │   ├── terrain/
│   │   │   ├── TerrainLOD.ts          # 流式地形、植被、城镇与材质混合
│   │   │   ├── RouteFeatures.ts       # 田野/森林/城镇/河谷/山地路线语义
│   │   │   └── RouteProfile.ts        # 连续线路高程与纵坡
│   │   ├── track/                     # 轨道、站区、隧道、河谷道路桥
│   │   ├── interior/WindowFrame.ts    # 面对面软座车厢与车窗前景
│   │   └── weather/                   # 天气粒子，始终在车厢前景之后
│   ├── journey.ts                     # 区间、经停与番茄钟规划
│   ├── audio.ts                       # 行驶声音
```

`ThreeCanvas` 先绘制外景，再清除深度并绘制独立的车厢前景场景。因此雨雪等外景透明物不会盖在窗框、座椅和内饰之上。相机的实时速度是 HUD、里程和音频的唯一遥测来源。

## 路线与场景约束

- `RouteFeatures` 是地貌、平行道路、城镇和隧道资格的公共事实来源；不能为单个分块重新随机决定工程结构。
- `RouteProfile` 同时驱动轨道、相机、站区、隧道、河道水位和河谷桥的纵向高程。
- 所有贴地的植被、建筑与道路应使用 `TerrainLOD.sampleHeight()` 或当前路线高程，不能用独立噪声近似高度。
- 河谷桥仅在河谷路线段预热，驶离后释放；站区与站前道路以 `roadCenterX(z)` 对齐。
- 近景车厢保持独立前景 pass；转动观察方向只能改变相机，不应让窗框跟随外景漂移。

## 旅程状态机

`setup → ride ⇄ dwell → done/abort`。经停站为 `dwell`，不计入专注时长。进站前预热站区，随后由 Three.js 相机执行物理制动；HUD、声音和里程与同一相机速度同步。

## 2026-09-04 坐席与窗景更新

用户已将当前方向改为坐席列车。默认车厢为面对面双人软座，六铺、卧具和爬梯已退出运行时。`SoftSeatCoach.ts` 单独组织织物高背椅、头枕套、扶手、小桌、书杯、褶皱窗帘和行李架；`WindowFrame.ts` 保留车体、玻璃、雨水及旅程控件。窗口扩大为 4.0 × 2.3 个场景单位，初版前景距离为 2.85；随后按用户反馈改为靠窗眼位，与玻璃相距 1.0 个场景单位，朝窗外略向前看。眼位与朝向统一定义在 `core/PassengerView.ts`，F2 可对比原走道眼位，保留受限转头。

F2 / `?debugCarriage=1` 可隔离车体、软座组、设备、玻璃、灯光和 HUD；可切到晴日田野、林地、湖畔、山地、雨天和夜间。场景跳转是开发检查功能，不代表完成真实旅程。
